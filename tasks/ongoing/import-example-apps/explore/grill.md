# grill 纪要（自问自答，只追细节）

1. **导入是否需要服务端内置示例接口？**
   不需要。agent-api 已有建应用与提交发布两条通用接口；前端把源文件作为 `files` 提交即可。新增内置接口会扩大服务端安全面且与包登记逻辑重复。→ 复用现有接口。

2. **示例源文件怎么进入浏览器？**
   仓库示例不在 agent-web 源码里。开发时由 vite 静态中间件从相对路径 `../examples/ai-apps` 读取；构建时复制到 `public/examples/ai-apps` 后由 Vite 照常打包进 `dist`。不引 `@sage/*`，保持浏览器 bundle 边界。→ 构建期复制 + dev 中间件。

3. **清单怎么来？**
   读取 `app.yaml` 只支持提取 `id` 与 `description` 不够稳；直接维护三个示例的 id、标题、简介与文件清单，文件内容仍从源包读取，避免复制内容。新增示例需同步清单，写进假设。→ 写死清单 + 动态读文件。

4. **重复导入怎么判定？**
   先看列表是否已有同 appId；已有则直接显示“已存在”。若本地列表落后导致 `APP_ALREADY_EXISTS`，同样按已存在处理，不放宽服务端语义、不覆盖。→ 前端预检 + 409 归类。

5. **导入一半失败（应用建成但发布失败）怎么办？**
   应用会以 active 但无 release 的状态留下，列表可点开；对话框显示失败原因并允许重试，重试时已存在的应用继续提交发布。不自动删除，避免误删用户刚创建的同名应用。→ 保留应用 + 可重试发布。

6. **导入成功后的落点？**
   刷新应用列表并在对话框内显示成功，提供“查看详情”；不自动跳转，方便连续导入其他示例。→ 留列表并刷新。

7. **是否需要 mock 模式支持导入？**
   mock 模式写操作统一被 `MOCK_READ_ONLY` 拒绝；导入按普通写操作处理，失败提示只读即可，不伪造成功。→ 不扩展 mock。
