边界规则与决策约束

本页面对应 docs/design/ 中 README.md / first-version-system-architecture.md / generic-agent-platform-final-architecture.md 的全部硬性约束。检查脚本与脚本见 platform/scripts/check-*.mjs。

依赖白名单

  • ✓ Agent Application → Agent Library（单向）
  • ✓ Chat Service → LocalAgentClient → Agent Library
  • ✓ Temporal Activity → LocalAgentClient → Agent Library
  • ✓ Task Router → Temporal Client Adapter → selected Temporal Cluster
  • ✓ Skill / Tool Runtime → CredentialProvider → Secret Manager
  • ✓ Engine Adapter → Kernel Capability Callback → Capability Broker → MCP/HTTP/Native/Sandbox Adapter
  • ✓ Kernel → Model Broker（Kernel 不直接接触 Provider SDK）

禁止依赖

  • ✕ Agent Library → Chat / Task / Temporal / Fastify / PostgreSQL
  • ✕ Agent Application → Pi 专有 API（统一过 harness-pi）
  • ✕ Chat / Task UI → Pi / Temporal / PostgreSQL
  • ✕ 模型 / 普通用户 → Temporal endpoint / Namespace / Task Queue
  • ✕ Temporal Workflow → LLM / Tool / 网络 / 数据库 I/O
  • ✕ Session / Checkpoint / Event / History / Trace → 明文 Secret
  • ✕ Engine Adapter → 直接访问 Provider 或 MCP connection
  • ✕ Engine Adapter → 自行签发 CheckpointRef / 持有硬预算余额

必须存 ref 而非存值

  • Chat/Task/Session 只保存 connection_ref 或 credential_ref。
  • Workflow History 不携带 LLM prompt 内容、密钥、Tool 大结果。
  • Tasks 只携带 AgentTaskSpec 引用 + digest；不携带完整 payload。
  • Capability Request 只携带 canonical input digest；不携带 Secrets。

状态 Owner（不可漂移）

状态Owner不允许做的事

Retry 语义

Queue / Activity delivery retry

同 Attempt · 同 Spec · 同 invocation_id

Temporal Activity 重投递保持不变，避免副作用重复执行。

Agent semantic retry

新 invocation · 复用 Effect/Usage receipt

通常仍在同 Attempt；已提交的 Effect/Usage receipt 必须可幂等复用。

配置漂移 / 不可兼容 Checkpoint

新 Attempt · 新 Spec

model / grant / target / runtime 变化时强制新 Attempt；不兼容 Checkpoint 恢复也强制新 Attempt。

EFFECT_UNKNOWN

停止自动重试

必须进入人工 resolution protocol；自动重试会被 Effect Ledger 拒绝。

MCP 定位

Agent Engine
  → Kernel Capability callback
  → Capability Broker
  → MCP / HTTP / Native / Sandbox Adapter
  → Semantic Capability Provider

MCP discovery + schema metadata → 仅描述能力，不产生 grant
MCP 新增 Tool → 已 admission 的 Spec 不能自动获得该 Tool

所有 Tool 调用必须过 Capability Broker；Effective grant = Spec grant snapshot ∩ live deny overlay ∩ principal/tenant scope ∩ approval ∩ current ledger budget。

Tool 分类与处理

  1. Semantic tools · 业务语义、强类型、首选
  2. Bounded generic tools · 浏览器 / 文件 / 代码检索，受控 sandbox / egress
  3. Infrastructure tools · SQL、db driver、任意 shell、任意 HTTP；默认不向 Agent 暴露；必须由受信 Provider 封装或经高等级审批

fail-closed 默认值

  • ! Registry / Policy / Model / Capability / Target / Ledger 不可用时默认 fail-closed
  • ! 只读 Interactive 场景的有限降级必须由显式 policy 允许
  • ! Live overlay（revocation / emergency deny / approval expiry / scope）只能撤权或 kill，不能加 Tool / Provider / Scope
  • ! EFFECT_UNKNOWN 禁止自动重试
  • ! 缺 provider fingerprint / runtime compatibility → fail closed
