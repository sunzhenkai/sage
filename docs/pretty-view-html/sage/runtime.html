Chat 短请求与长请求

短 Chat

UI → Chat Service → LocalAgentClient → Agent Library → SSE；不承诺 API 进程崩溃后继续生成，但用户消息已持久化，可手动 retry。

需要在产品前老实失败，避免伪装为持久任务。

长 Chat（提升为 Task）

UI → Chat Service → Task Service → Task Router（受信任） → Temporal WorkflowTargetSnapshot → Temporal Cluster → Environment Worker → LocalAgentClient → Agent Library；Chat 中显示 task_card。

长请求、复杂 Tool 或高风险 Tool 必须提升 durable。

Workflow 与 Activity 边界

AgentTaskWorkflow
├── initialize
├── runAgentSlice   Activity
├── persistCheckpoint  Activity
├── wait Signal / Timer（按任务需要）
├── continue / retry
└── complete / fail / cancel

边界

Workflow 只包含确定性状态、Timer、Signal、Retry 策略和稳定引用。不允许在 Workflow 内执行 LLM / Tool / 业务 API / DB / Artifact I/O / Credential 解析 / Checkpoint 持久化——这些必须进 Activity。

Task Router 算法

  1. 解析并校验 TaskType。
  2. 读取 tenant / environment / data-residency 约束。
  3. 从 Registry 过滤 enabled + healthy Target。
  4. 匹配 allowed_task_types、capabilities、isolation。
  5. 按显式环境、优先级和区域策略排序。
  6. 选择一个 Target，写入 WorkflowTargetSnapshot / CoordinatorTargetSnapshot。
  7. 使用对应 Temporal Client 启动 Workflow。

无匹配目标返回 ROUTING_UNAVAILABLE，不得回退到 API 进程内执行。

状态所有权（Single Authority）

状态Owner
Chat Session、Message、SummaryPostgreSQL Chat Store（chat_sessions / chat_messages / chat_message_parts）
Workflow History、Timer、Signal、Activity Retry目标 Temporal Cluster
Task 产品状态、WorkflowTargetSnapshot、查询视图PostgreSQL Task Store（仅 projection）
Agent Session、Run、Checkpoint、Spec、ReceiptPostgreSQL Agent State（agent_run_records / agent_checkpoint_commit_operations / agent_effect_ledger / agent_usage_accounts / agent_security_audit / ...）
文件、附件、报告、checkpoint bodyArtifact Store（S3-compatible + KMS 加密）
明文密钥、OAuth Token、mTLS KeySecret Manager
connection_ref / secret_ref 元数据CredentialProvider / Application DB

禁止反向 authority

Projection / cache / event / trace / prompt context 都不能反向成为 authority。Task Store 是产品查询投影，不是 Workflow 执行真相。检测到不一致时使用固化 WorkflowTarget 查询 Temporal 并修复。

故障与降级（v1.1）

故障行为
API 在短 Chat Run 中重启Message 保留，当前 Run 失败，用户 Retry
目标 Temporal 启动前不可用Router 按显式策略选其他健康 Target，否则 ROUTING_UNAVAILABLE
已启动 Temporal Cluster 不可用固定 Target，等待恢复或显式迁移，不静默跨 Cluster
环境 Worker 重启Temporal 重新投递 Activity，副作用依赖幂等键
Task Store 不可用Workflow 可继续；产品投影延迟，恢复后对账
Agent State 不可用Activity 失败重试，不推进 Checkpoint 边界
Secret Manager 不可用需要凭据的操作 fail closed
Artifact Store 不可用不把大结果塞入 History/Task Store，Activity 失败或等待
SSE 中断UI 使用 afterSequence 恢复 Chat/Task Timeline

跨 Cluster 故障语义

Workflow 启动前

Router 可在健康 Target 间选择

首选不可用时按明确策略选择次优目标。Worker 死后 Temporal 重新投递 Activity，不重新选 Target。

Workflow 启动后

Cluster 不可用 = 固定 Target

保留 Task 与 WorkflowTargetSnapshot；query / signal / cancel 返回目标不可用；不在另一个 Cluster 静默创建相同 Workflow。

显式迁移

需要审计与新 Workflow

外部 Checkpoint · 稳定幂等键 · 新 workflow_id · 新 TargetSnapshot · 迁移审计。v1.1 不承诺自动跨 Cluster 续跑。
