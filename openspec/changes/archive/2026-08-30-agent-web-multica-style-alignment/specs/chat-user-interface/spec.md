## MODIFIED Requirements

### Requirement: 归档视图与对话行操作

Chat landing SHALL 以常驻列表栏形态呈现：列表栏内提供未归档与归档两个视图的切换入口（如「对话 / 归档」），以 `aria-pressed` 或等价可访问状态表达当前视图；切换 SHALL 以 history API 的 `archived` 参数重新加载列表，搜索与 status 过滤在两个视图均可用。历史行 SHALL 提供行内操作且不破坏行的主链接导航：未归档视图提供「归档」；归档视图提供「恢复」与「彻底删除」。彻底删除 SHALL 为两步显式确认：首次点击进入行内确认态并明示不可撤销，只有显式确认后才发出 `DELETE` 请求；取消 SHALL 不发请求并退出确认态。操作成功 SHALL 以行移除与完成式短句反馈表达（如「已归档」），失败 SHALL 复用既有错误横幅；归档视图 SHALL 提供区别于主列表的空态单行文案。列表栏空态 SHALL 为单行短句，SHALL NOT 解释「开始对话始终需要明确操作」等机制背景。

#### Scenario: 视图切换请求归档列表
- **WHEN** 用户切换到归档视图
- **THEN** UI 以 `archived=true` 请求 history，仅展示已归档 session，再切回时以缺省参数请求

#### Scenario: 归档操作移出主列表
- **WHEN** 用户在未归档视图点击某行「归档」且请求成功
- **THEN** 该行从未归档列表移除并出现成功反馈，不发生整页跳转

#### Scenario: 两步删除确认
- **WHEN** 用户在归档视图点击「彻底删除」
- **THEN** 该行进入确认态并展示不可撤销警示；用户确认后发出 `DELETE`，成功后该行移除并出现成功反馈

#### Scenario: 取消删除不发请求
- **WHEN** 用户在确认态点击取消
- **THEN** UI 不发出 `DELETE` 请求，该行回到普通操作态

#### Scenario: 删除失败保留行
- **WHEN** 确认后的 `DELETE` 请求失败
- **THEN** 该行保留在归档列表中，UI 展示错误横幅

#### Scenario: 归档视图空态
- **WHEN** 归档视图加载成功且无归档 session
- **THEN** UI 展示归档专属空态单行文案，而非主列表空态或错误状态

#### Scenario: 未选中会话时内容区为空态
- **WHEN** 对话视图未携带 `session` 参数
- **THEN** 列表栏展示会话清单，内容区展示居中单句空态（如「选择一个对话，或点 + 新建」），不渲染整页历史页头与副标题

## ADDED Requirements

### Requirement: 对话空态与时间线空态收敛

Chat 视图的空状态 SHALL 为居中图标加单句短文案：时间线空态 SHALL NOT 使用「从明确目标开始」加整句说明的双行说明形态，SHALL 收敛为单句引导（如「问点什么开始」）。引导性快速提示（quick prompts）SHALL 保留为输入区附近的动作 chips，不承担页面级说明职责。

#### Scenario: 时间线空态单句化
- **WHEN** 打开一个没有任何事件的会话
- **THEN** 对话区展示居中单句空态，不出现双行标题加整句说明的形态
